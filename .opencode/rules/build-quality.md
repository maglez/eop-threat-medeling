- Build MUST pass before any PR merge (`mvn verify` in CI)
- Code style enforced by `checkstyle` against the repo's own `checkstyle.xml` (4-space indent, 140-char line limit — NOT Google Java Style) — violations fail the build
- Static analysis via `spotbugs` — high/medium severity findings fail the build
- Code coverage via `jacoco` — minimum 80% instruction and 70% branch coverage, both evaluated over the whole bundle (`pom.xml:169`) with no exclusions and no per-class rule; the branch limit was restored by EOP-15 slice B once the domain had branches to measure — see ADR-006 as amended by ADR-031
- `maven-enforcer-plugin` enforces: JDK >= 21, dependency convergence (no version conflicts), no banned dependencies
- **Prose is a build gate too.** Documentation-integrity tests in `src/test/java/org/maglez/eop/docs/` run as part of the same `verify` phase and read repository files as text: `TrickPlayExceptionOriginTest` (EOP-14) pins an ADR-023 paragraph to the adapter, `AdrIndexConsistencyTest` (EOP-32) holds `docs/adr/README.md` against every ADR's status line, `DeckArithmeticClaimsTest` (EOP-93) checks deck-arithmetic claims across **all** of `docs/**/*.md` and `src/**/*.java`, and `EnumMirrorParityTest` (EOP-105) holds four mirrored enums (`PlayerRole`, `SessionStatus`, `ConnectionStatus`, `StrideCategory`) in three-way agreement across the Java enum, the `enum:` lists in `docs/api/openapi.yml` and the `as const` arrays in `ui/src/api.ts`, and `MermaidSequenceTextTest` (EOP-000) forbids `;` and `#` in every label of every Mermaid `sequenceDiagram` fence under `docs/**/*.md`. So editing a Markdown file anywhere under `docs/` can turn the build red — and so can editing `docs/api/openapi.yml` or `ui/src/api.ts`, which is the surprising direction: a front-end enum rename that passes `npm run verify` in `ui/` fails `./mvnw verify`. Three consequences worth internalising: their matchers are phrase lists rather than semantic analysis, so **a green build is not proof that documentation is correct** — it only proves the specific phrasings that have gone stale here before are absent; their *coverage* is likewise a hand-written list, so nothing detects a fifth mirrored enum added to `ui/src/api.ts` without a row in `EnumMirrorParityTest.mirrors()` — and that is not hypothetical, because `StrideCategory` was exactly such an unregistered mirror, found by a review agent rather than by the build, and registered only during EOP-105's own gate round; a further consequence of the same shape is that `typeScriptArrayValues` recognises only the `export const NAME = [...] as const;` idiom, so registering a mirror written as a bare union means rewriting the declaration first; and if one of these guards ever becomes unfireable (invariant B is meaningless once no supported table size divides the deck evenly), **delete it rather than leave it passing**, per the branch-coverage lesson in ADR-006. `MermaidSequenceTextTest` sits differently to the other four on the first of those consequences and squarely inside the third: it is structural rather than a phrase list, so it holds for diagrams nobody has written yet — but it proves only that two characters are absent, never that a diagram renders or says anything true, and its own coverage is the hand-written `MINIMUM_SEQUENCE_DIAGRAMS` floor that stops it silently matching nothing. See ADR-006 as amended 2026-08-18 (EOP-93), 2026-08-19 (EOP-105) and 2026-08-20 (EOP-000)
