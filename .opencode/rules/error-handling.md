- All API error responses follow RFC 9457 Problem Details (`application/problem+json`)
- Single `@ControllerAdvice` — never per-controller exception handlers
- Domain exceptions live in `org.maglez.eop.*` with zero Spring imports
- Global handler maps: domain exception → HTTP status (e.g., `GameNotFoundException` → 404, `IllegalMoveException` → 409)
- `@Valid` validation errors produce `ValidationProblemDetail` with field-level messages
- Every known exception must have a unit test verifying its HTTP status mapping
- The `GlobalExceptionHandler` itself must be unit-tested for every mapped exception type

## Client side — the browser's own boundary (ADR-045)

The rules above govern errors the server *emits*. These govern errors the browser *raises about the server*, which is a different boundary with a different vehicle.

**This boundary is not a security control, and must never be cited as one.** It closes a maintenance hazard and converts silent misbehaviour into a loud failure — nothing more. Nothing on the client is authoritative: there is no authentication (ADR-015), the only privilege is enforced in the domain (`GameSession.start`), and `ui/Caddyfile` serves bundle and API from one origin (ADR-017), so a server able to inject a bogus payload can already serve arbitrary JavaScript. Say "structurally and enumerably validated", never "trusted" or "secured".

- **Parse response bodies, never assert them.** A `as SomeDto` cast in `ui/src/api.ts` is a compile-time claim that TypeScript erases at runtime, so an out-of-contract value reaches React state and every comparison against it silently evaluates `false`. Each JSON-returning helper must pass its body through a `parseX(value: unknown): X` function in the same module. The rule is *a helper that reads no body gets no parser* — so a `204`, a void POST, and the SSE doorbell (whose `data:` frames carry no DTO, and whose triggered re-fetch **is** parsed) are all correctly parser-free. ADR-045 §4 holds today's roster; do not copy it here, because it goes stale the first time a helper is added
- **`ui/src/api.ts` is the only place a response is parsed.** No component may cast a payload; if a shape has no parser, add one there rather than validating in a component. The `parse*` functions are deliberately **not exported**, which is what makes this a compiler-enforced property rather than a convention a reviewer must police. Note this rule scopes to *responses*: `ui/src/App.tsx`'s `isStoredSession` guard validates `sessionStorage`, a different boundary, and is not an exception to it
- **A rejected payload throws `ContractViolationError`** — `extends ApiError` with `status = 502`. Extending is load-bearing: every component already catches `instanceof ApiError` and renders `.message` through `ErrorSummary`, so a standalone class would be missed by every existing catch and surface as a blank screen. `502` rather than `response.status`, because the server said `200` and reusing that status would lie
- **Never degrade to a partial render** — dropping the offending field and rendering the rest reinstates the exact defect: an out-of-contract value producing a plausible-looking UI
- **The message names the DTO and the field, never the payload** (e.g. `SessionStateDto.status: expected one of LOBBY, IN_PROGRESS, COMPLETED, ABANDONED`), so a response body cannot be laundered into rendered output. This binds *keys* as well as values: a map whose keys the server chooses (`capturedBySuit`) must report only the field, as in `expected every value to be a finite number` — naming the offending key would reflect an attacker-influenced string into the error summary
- **Strictness is bounded on purpose:** object-ness, presence and `typeof` of required fields, arrays actually arrays, and enum fields checked with the existing `is*` guards. **No** format validation — no UUID regex, no ISO-8601 parsing, no range checks. Because of this bound, describe the DTOs as *structurally and enumerably* validated; "validated at the boundary" unqualified over-claims
- **Consume the four `is*` guards, never re-inline their member lists.** `isPlayerRole`, `isSessionStatus`, `isConnectionStatus` and `isStrideCategory` are the seam, and `EnumMirrorParityTest` only holds the *arrays* in step with the Java enums and `docs/api/openapi.yml` — a hand-written duplicate of a member list inside a parser is invisible to it
- **One Vitest rejection case per parsed boundary**, asserting an out-of-contract enum value throws rather than being admitted. Note that a test using `vi.spyOn(api, …)` bypasses the parsers entirely and is therefore not evidence they work; only tests that stub global `fetch` exercise them
- Nothing detects a field added to a DTO interface but not to its parser — the interface still typechecks, and because a parser *reconstructs* rather than passing through, the field is silently dropped and arrives `undefined`. That gap is enforced by review, and it is the trigger ADR-009 names for revisiting generated validators — or for a text-comparison build gate in the style of `src/test/java/org/maglez/eop/docs/`, which would close it without a generator
